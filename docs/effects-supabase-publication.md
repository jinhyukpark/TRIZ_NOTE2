# Effects Supabase 게시 — 2026-09-24

프로젝트: TrizNote2 (`sovzalkrotgvnqvpfkjd`). 이번 17개 신규 항목이 대상이며, 기존 14개는 로컬 구현을 유지한다.

## 서버 저장

- `public.effect_content`: 17개 게시 레코드, 85단계.
- JSON payload: 4개 언어 제목/요약/설명/핵심 원리, 단계, 출처 영상, 분류, 목록 명칭, 장비 역할, 연결선 좌표, 이미지 URL/크기/SHA-256, 설명 도형 및 번역 캡션.
- Storage `effect-content`: 목록 17개 + 상세 85개 = 102개 PNG, 202,169,071바이트.
- 콘텐츠 해시가 포함된 버전 경로로 게시하여 기존 이미지 덮어쓰기를 피한다.
- 공개 앱 콘텐츠이므로 게시 레코드와 이미지는 공개 읽기. DB RLS가 활성화되어 있고 anon/authenticated에는 SELECT만 허용한다. 클라이언트 업로드 정책은 만들지 않았다.
- 관리자 자격 증명은 CLI에서 게시 프로세스 메모리로만 전달한다. 앱, 파일, 로그에 저장하지 않는다.

## 앱 연결

Effects 메뉴 진입 시 서버 콘텐츠를 조회한다. 완전한 5단계 및 4개 언어, 신뢰하는 Storage URL을 검증한 레코드만 적용한다. 설명 도형도 서버 JSON을 네이티브 UI로 렌더링한다. 네트워크 실패/잘못된 레코드는 번들 콘텐츠를 유지하며, 이미지 다운로드 실패 시 번들 이미지로 대체한다.

렌더러 자체는 앱 코드에 남는다. 새로운 렌더링 종류나 새 항목 ID를 추가할 때에는 현재 앱 코드/번들도 함께 갱신해야 한다. 서버가 임의 코드를 실행시키는 방식은 사용하지 않는다.

## 운영 명령

`node scripts/publish-effects.mjs`: 게시 대상 수량 확인만 수행.

`node scripts/publish-effects.mjs --publish`: 지정된 TrizNote2 프로젝트에 버전 이미지 업로드, 102개 이미지 재다운로드 SHA-256 대조 후 DB upsert 및 read-back 대조. Supabase CLI의 관리자 로그인이 필요하다. 동일 해시 이미지가 있으면 재사용한다.
